# Silver Park Rangers 스쿼드 관리 — 기획

> 최종 수정: 2026-10-19 · 상태: 기획 확정, 프로젝트 세팅 대기

## 1. 목적

매주 한 번 다른 팀과 경기하는 우리 팀의 스쿼드 편성을 쉽게 만든다. 참석 투표 → 쿼터별 스쿼드 편성 → 공유까지 한곳에서 끝낸다.

운영 원칙

- **비용 0원**: 비상업용이라 모든 서비스를 무료 플랜 안에서만 쓴다. 카드 등록이 필요한 플랜도 쓰지 않는다.
- **우리 팀 전용**: 관리자가 승인한 사람(멤버, 용병)만 쓸 수 있다.

용어

- **매치**: 하루 일정 하나 (예: 10/25 10:00~13:00 vs OO FC)
- **쿼터**: 매치 안의 경기 하나(25~30분). 기본 6쿼터

## 2. 기술 스택

| 영역 | 선택 | 메모 |
|---|---|---|
| 형태 | 웹 (PWA로 홈 화면 추가) | 카톡 링크로 바로 열리게. 앱 설치 허들 없음 |
| 프레임워크 | Next.js (App Router) + TypeScript | b-match-admin과 같은 조합 |
| UI | Tailwind + shadcn/ui | |
| 드래그 앤 드롭 | dnd-kit | 모바일 터치 지원 |
| 데이터 불러오기 | TanStack Query + Supabase Realtime | Realtime은 승인 대기 뱃지, 동시 편집용 |
| DB · 인증 | Supabase (Postgres, Auth, RLS) | 카카오 로그인 기본 지원 |
| 이미지 익스포트 | modern-screenshot | 브라우저에서 PNG 생성 |
| 카톡 공유 | Kakao JS SDK 공유 + `next/og` 미리보기 이미지 | 8장 참고 |
| 테스트 | Vitest | 자동 배치 로직 검증 |
| 호스팅 | Vercel Hobby | 비상업용 조건에 맞음 |

무료 플랜에서 주의할 점

- Supabase 무료 프로젝트는 7일 동안 안 쓰면 일시정지된다 → Vercel Cron(하루 1회)으로 DB에 요청을 보내서 막는다.
- Supabase 무료 플랜은 활성 프로젝트가 2개까지다 → 시작 전에 남은 자리를 확인한다.
- 구글 로그인은 카톡 인앱 브라우저에서 막힌다(`disallowed_useragent`) → 카카오 로그인만 쓴다.
- 웹 카카오 로그인은 OAuth 리다이렉트 방식이다(b-match는 네이티브 SDK + idToken 방식). 카카오 콘솔에 Supabase 콜백 URL을 등록해야 한다. 카카오 앱은 b-match와 따로 만든다.
- 카톡은 링크 미리보기 이미지를 캐시한다 → 미리보기 URL에 `?v=수정시각`을 붙인다.
- `next/og`는 한글 폰트를 직접 넣어줘야 한다 → 필요한 글자만 남긴 Pretendard를 쓴다.
- 카톡 인앱 브라우저에서는 이미지 다운로드가 안 될 수 있다 → 초반에 실제 폰으로 확인하고, 안 되면 공유 시트(Web Share API)나 "길게 눌러 저장"으로 대신한다.

## 3. 사용자와 권한

권한(역할)과 구분(멤버 / 용병)은 따로 관리한다. 권한은 세 단계다.

| 권한 | 누구 | 할 수 있는 것 |
|---|---|---|
| 어드민 | 선수가 아닌 운영용 전용 계정. 이메일·비밀번호로 로그인한다 | 관리자가 하는 일 전부 + **관리자 지정·해제**, 관리자 휴면 처리 |
| 관리자 | 멤버 중 어드민이 지정한 사람 | 일반 기능 + 가입 승인·거절, 멤버/용병 구분, 일반 멤버 휴면 처리, 매치 생성, 스쿼드 편성, 통계 |
| 일반 | 승인된 멤버·용병 | 참석 투표, 공개된 스쿼드 보기, 내 프로필 수정 |

- 어드민 계정은 선수가 아니라서 멤버 목록·참석·스쿼드에 나오지 않는다. 그래서 `members` 가 아니라 `owners` 테이블에 둔다. 관리 화면(`/admin`)만 쓴다.
- 어드민 계정은 Supabase 대시보드에서 만들고 SQL Editor 로 `owners` 에 넣는다(docs/SETUP.md §4). 앱에서는 누구도 어드민이 될 수 없다.
- 관리자끼리 서로 휴면 처리하지 못한다. 관리자의 휴면·해제는 어드민만 한다.

| 구분 | 의미 | 누가 보나 |
|---|---|---|
| 멤버 | 정식 멤버. 관리자가 승인할 때 지정 | **관리자만** |
| 용병 | 링크로 가입한 용병. 멤버 통계(참석률 등)에서 빠진다. 나중에 멤버로 바꿀 수 있다 | **관리자만** |

- 일반 사용자 화면(참석자 목록, 쿼터 보드, 공유 이미지)에는 멤버 / 용병 표시가 나오지 않는다.
- 구분 값은 일반 사용자가 읽을 수 없게 관리자 전용 테이블에 따로 저장한다(7장 `member_admin_info`).
- 계정 상태: `온보딩 전 → 승인 대기 → 승인 | 거절`. 승인된 뒤에도 관리자가 휴면 처리할 수 있다. 잘못 거절했으면 거절 목록에서 다시 승인한다.
- 첫 관리자는 어드민 계정이 관리 화면에서 지정한다.

## 4. 가입 · 승인 흐름

1. 단톡방이나 용병에게 서비스 링크를 보낸다.
2. 카카오 로그인을 한다.
3. 온보딩 화면에서 실명, 주발, 선호 포지션을 입력한다 (5장).
4. 승인 대기 화면으로 넘어간다. 승인 전에는 아무 기능도 쓸 수 없다.
5. 관리 화면에 가입 신청 수가 뜬다. 관리자(또는 어드민)는 입력된 실명과 카카오 닉네임·프로필 사진을 같이 보고 본인이 맞는지 확인한 뒤, 승인(멤버 / 용병 선택)하거나 거절한다.
6. 승인되면 바로 서비스를 쓸 수 있다.

### 접근 차단은 두 겹으로 한다

URL은 공개라서 누구나 접속 자체는 할 수 있다. 그래서 다음 두 겹으로 막는다.

- **화면**: Next.js `proxy.ts`(예전 이름 middleware)가 로그인 여부와 계정 상태를 확인하고, 해당 사용자를 `/login`, `/onboarding`, `/pending`으로 보낸다.
- **데이터**: Supabase 접근 정책(RLS)으로 승인된 사람만 읽고 관리자만 쓰게 한다. 브라우저에 노출되는 Supabase 키로 API를 직접 호출해도, 승인 안 된 사람은 아무것도 읽지 못한다. 화면 차단만으로 부족한 이유가 이것이다.
- 사용자가 자기 역할이나 상태를 직접 바꾸지 못하게, 해당 컬럼은 권한 설정이나 트리거로 막는다.
- 예외는 카톡 공유용 경로 하나뿐이다(8장).

## 5. 프로필 항목

실명만 텍스트로 입력하고, 나머지는 모두 선택형이다.

| 항목 | 입력 방식 | 규칙 |
|---|---|---|
| 실명 | 텍스트 | 필수 |
| 주발 | 왼발 / 오른발 | 복수 선택(둘 다 고르면 양발), 최소 1개 |
| 선호 포지션 | 아래 7개 중 선택 | 1~3개, 고른 순서가 우선순위 |

### 포지션 분류

| 코드 | 이름 | 비고 |
|---|---|---|
| `FW` | 공격수 | |
| `AM` | 공격형 미드필더 | |
| `WG` | 윙 | 4-4-2의 좌우 미드필더 포함 |
| `MF` | 미드필더 | 수비형 미드필더 포함 |
| `WB` | 윙백 | 풀백 포함 |
| `CB` | 센터백 | |
| `GK` | 골키퍼 | |

포메이션의 슬롯마다 이 7개 중 하나가 붙는다. 그래서 스쿼드 빌더에서 그 슬롯을 선호하는 선수를 강조할 수 있고, 자동 배치(6장)와 포지션별 출전 통계에도 쓸 수 있다.

- **4-3-3**: GK, WB×2, CB×2, MF×3, WG×2, FW
- **4-4-2**: GK, WB×2, CB×2, MF×2, WG×2, FW×2
- **커스텀**: 슬롯을 자유롭게 배치하고 슬롯마다 포지션을 지정해서 저장한다.

## 6. 쿼터 운영과 자동 배치

### 매치 기본값

- 6쿼터, 10:00~13:00. 관리자가 매치마다 바꿀 수 있다.
- 쿼터 시작 시각은 전체 시간을 쿼터 수로 똑같이 나눠서 정한다. 기본값이면 30분 간격으로 10:00, 10:30, … 12:30에 시작하고, 실제 경기는 그 안에서 25~30분 한다.
- 쿼터당 11명(필드 10 + 골키퍼 1). 커스텀 포메이션은 인원이 달라도 된다.

### 참석 투표

- 참석 / 불참 / 미정 중에서 고른다. 마감 전에는 몇 번이고 바꿀 수 있다.
- 투표 마감은 관리자가 매치를 만들 때 정한다. **따로 정하지 않으면 매치 시작 시각에 마감한다.**
- 참석이면 **도착 시간**과 **떠나는 시간**을 고른다. 쿼터 시작 시각 단위로 선택하고, 기본값은 "처음부터"와 "끝까지"다.
  - 예: 11:00에 도착하면 11:00 쿼터부터, 12:00에 떠나면 11:30 쿼터까지 뛸 수 있다.
- 늦게 오는 사람과 일찍 가는 사람은 같은 규칙으로 처리한다(6장 자동 배치).
- 미리 알린 늦은 도착만 받는다. 예고 없는 지각은 따로 처리하지 않는다.
- 시간은 쿼터 번호가 아니라 시각으로 저장한다. 그래야 관리자가 매치 시간을 바꿔도 "12시에 간다"는 의미가 그대로 남는다.

### 골키퍼

- **전담 키퍼**: 선호 포지션 1순위가 GK인 사람이다. 뛸 수 있는 모든 쿼터에서 키퍼를 맡고, 필드 배분에서는 빠진다. 1순위 GK가 2명 이상 오면 키퍼 쿼터를 똑같이 나눈다.
- **수동 차출**: 전담 키퍼가 불참하거나 일부 쿼터에만 있으면, 그 쿼터의 키퍼 자리는 비워두고 경고를 띄운다. 관리자가 직접 멤버를 골라 넣는다. 자동으로 뽑지 않는다.
- **키퍼로 뛴 쿼터는 출전으로 세지 않는다.** 차출된 사람도 필드 출전은 다른 사람과 똑같이 보장받는다.
- 키퍼 자리를 먼저 채우고 자동 배치를 누르면, 키퍼 자리는 그대로 두고 필드만 짠다. 차출된 사람은 키퍼로 뛰는 쿼터에서는 필드 후보에서 빠진다.

### 자동 배치 규칙

관리자가 빌더에서 "자동 배치"를 누르면 아래 순서로 전 쿼터의 필드를 채운다. 그다음 드래그로 고친다.

1. **보장 출전 수**: 필드 슬롯 총합(키퍼 자리 제외, 6쿼터 × 10 = 60)을 필드 선수에게 최대한 똑같이 나눈다.
   - 모두 n 또는 n+1쿼터를 뛴다. 사람 사이의 차이는 최대 1쿼터다.
   - 예외: 그렇게는 필드를 다 채울 수 없을 때만 상한을 n+2, n+3 … 으로 올린다. 사람이 남는데 필드를 비워 두지는 않는다. 무작위 입력 3,000개로 시험했을 때는 이 예외가 한 번도 필요하지 않았다.
   - 뛸 수 있는 쿼터 수보다 많이 줄 수는 없다. 늦게 오거나 일찍 가서 못 채운 몫은 나머지에게 다시 나눈다.
   - 예: 필드 17명이면 60 ÷ 17 ≈ 3.5 → 전원 최소 3쿼터, 그중 9명은 4쿼터.
2. **쿼터별 선발**: 앞 쿼터부터 채운다. 한 쿼터의 10명은 아래 순서로 뽑는다.
   1. **반드시 넣을 사람**: 남은 가능 쿼터를 전부 뛰어야 보장 수를 채울 수 있는 사람. 그래서 일찍 가는 사람은 앞 쿼터에, 늦게 오는 사람은 도착 직후 쿼터에 먼저 들어간다.
   2. **급한 사람**: "남은 보장 수 ÷ 남은 가능 쿼터"가 큰 사람부터. 그래서 쉬는 쿼터가 한쪽으로 몰리지 않는다.
   3. **남는 자리(n+1번째 쿼터)**: 그 쿼터 포메이션에서 아직 비어 있는 포지션을 선호하는 사람 먼저, 같으면 무작위다. 무작위라서 다시 누르면 다른 조합이 나올 수 있다.
3. **포지션 배치**: 쿼터마다 선발된 10명을 슬롯에 놓는다. 선호 1순위 3점, 2순위 2점, 3순위 1점으로 계산해서 합이 가장 큰 배치를 고른다.
4. **경고**: 다음 경우를 빌더에 표시한다.
   - 보장 출전 수에 못 미치는 사람
   - 필드 10명을 못 채우는 쿼터
   - 키퍼가 빈 쿼터
5. **다시 배치**: 자동 배치는 몇 번이고 다시 누를 수 있다. 다시 누르면 키퍼 자리는 유지하고 필드 배치는 새로 짠다(확인창을 띄운다).

자동 배치는 브라우저에서 도는 순수 TypeScript 함수로 만든다(서버 비용 없음). 위 규칙은 Vitest 단위 테스트로 검증한다.

## 7. 화면 목록

### 게이트 (승인 전)

어드민 계정은 `/login/admin` 에서 이메일·비밀번호로 로그인하고, 관리 화면(`/admin`)만 쓴다.

| 경로 | 내용 |
|---|---|
| `/login` | 카카오 로그인 |
| `/onboarding` | 실명, 주발, 선호 포지션 입력 |
| `/pending` | 승인 대기 / 거절 안내 |

### 일반 (멤버 · 용병)

| 경로 | 내용 |
|---|---|
| `/` | 다가오는 매치와 내 투표 상태 |
| `/matches/[id]` | 참석 투표(도착 / 떠나는 시간 포함), 참석자 목록. 스쿼드가 공개되면 쿼터 보드(포메이션 보기 / 출전표 보기) |
| `/me` | 주발, 선호 포지션 수정 |

**출전표**는 선수 × 쿼터 표에 출전 쿼터를 ●로 표시한 것이다. 6쿼터면 포메이션 그림 6장보다 "나 언제 뛰지?"를 찾기 쉽다.

### 관리자

| 경로 | 내용 |
|---|---|
| `/admin` | 가입 신청 수, 멤버 수, 다가오는 매치 |
| `/admin/members` | 가입 신청(멤버로 승인 / 용병으로 승인 / 거절), 멤버 목록(멤버↔용병, 휴면·복귀, 어드민만 관리자 지정·해제), 휴면·거절 목록 |
| `/admin/matches` | 매치 생성·수정(날짜, 시작·끝 시간, 쿼터 수, 장소, 상대, 투표 마감), 매치 후 실제 출석 확정 |
| `/admin/matches/[id]/squad` | 스쿼드 빌더 |
| `/admin/formations` | 커스텀 포메이션 관리 |
| `/admin/stats` | 통계 (2차) |

### 스쿼드 빌더

- 한 화면에 쿼터 탭(시간 표시), 경기장, 벤치(그 쿼터에 뛸 수 있지만 아직 배치 안 된 사람)를 같이 띄운다.
- "자동 배치" 버튼으로 전 쿼터의 필드를 한 번에 채운다(6장).
- 키퍼 자리가 비면 경고가 뜬다. 관리자가 아무 멤버나 키퍼 자리로 드래그해서 차출한다.
- 포메이션 프리셋을 고르거나 커스텀 포메이션을 불러온다. 현재 배치를 새 포메이션으로 저장할 수도 있다.
- 벤치와 슬롯 사이, 슬롯과 슬롯 사이를 드래그로 오간다.
- 선수 칩에는 다음을 표시한다.
  - 출전 쿼터 수 / 보장 쿼터 수 (예: 3/3). 키퍼로 뛴 쿼터는 "키퍼 1"처럼 따로 표시하고 출전 수에는 넣지 않는다.
  - 뛸 수 있는 시간
  - 선호 포지션과 주발
  - 용병 표시(관리자 화면이라서 보임)
- 이전 쿼터를 복사해서 시작할 수 있다.
- 관리자가 "공개"를 누르기 전에는 멤버에게 보이지 않는다.
- 이미지 익스포트: 쿼터별 한 장씩, 6쿼터를 2×3으로 모은 한 장, 출전표 한 장.

## 8. 카톡 공유

- 공유 카드에 선수 이름이 들어간다.
- 카카오 서버는 로그인 없이 미리보기를 가져간다. 그래서 공유 전용 공개 경로 `/s/[share_token]`을 따로 둔다.
  - 이 경로는 미리보기 메타태그(제목, 이미지)만 내려주고, 사람이 열면 `/matches/[id]`로 보낸다. 거기서 승인된 사람만 볼 수 있다.
  - `share_token`은 추측할 수 없는 랜덤 값이다. 매치 번호를 바꿔 넣는 식으로 다른 매치를 볼 수 없다.
- 미리보기 이미지에는 1쿼터 포메이션(이름 포함)과 "6쿼터 · 18명 · 10:00~13:00" 같은 요약을 넣는다. 카드 한 장에 66명분 이름을 다 넣으면 읽을 수 없어서다. 전체는 링크나 익스포트 이미지로 본다.

## 9. 데이터 모델 (초안)

| 테이블 | 주요 컬럼 | 메모 |
|---|---|---|
| `members` | `id`(= auth user id), `real_name`, `kakao_nickname`, `avatar_url`, `feet`(foot[]), `preferred_positions`(position[], 1~3개, 순서 = 우선순위), `role`(admin / user), `status`(pending / approved / rejected / inactive), `approved_by`, `approved_at` | 용병도 가입하므로 선수 = 계정 |
| `owners` | `user_id`(= auth user id) | 어드민 전용 계정. 쓰기 정책이 없어 SQL Editor 로만 넣는다. `approved_by`·`created_by` 는 어드민도 가리킬 수 있게 `auth.users` 를 참조한다 |
| `member_admin_info` | `member_id`, `member_type`(member / guest) | 관리자만 읽기·쓰기. 이후 관리자 메모도 여기에 둔다 |
| `matches` | `date`, `starts_at`(기본 10:00), `ends_at`(기본 13:00), `quarter_count`(기본 6), `venue`, `opponent`, `vote_deadline`(null 이면 매치 시작에 마감), `squad_published_at`, `share_token` | 날짜·시각은 한국 시간 |
| `match_attendance` | `match_id`, `member_id`, `response`(yes / no / maybe), `arrive_at`(null = 처음부터), `leave_at`(null = 끝까지), `attended`(null = 미확정) | 투표와 실제 출석을 따로 저장해야 노쇼율과 참석률을 계산할 수 있다 |
| `formations` | `name`, `is_preset`, `slots` jsonb `[{position, x, y}]` | 4-3-3, 4-4-2는 시드 데이터로 넣는다 |
| `quarters` | `match_id`, `number`, `formation_name` | 쿼터 시각은 매치 시간에서 계산한다 |
| `quarter_slots` | `quarter_id`, `slot_index`, `position`, `x`, `y`, `member_id`(빈 슬롯이면 null) | 포메이션 좌표를 복사해서 저장한다 → 원본 포메이션을 고쳐도 지난 매치는 그대로. 출전 쿼터 수와 포지션별 출전은 이 테이블에서 바로 집계한다. `position = GK`인 칸은 출전 수에서 빼고 키퍼 쿼터로 따로 센다 |

## 10. 단계별 범위

### 1차 — MVP (바로 다음 매치부터 쓰기)

- 카카오 로그인, 온보딩, 승인 게이트(화면 + RLS) — 완료
- 어드민 전용 계정, 멤버 관리(승인 시 멤버 / 용병 지정, 휴면, 어드민의 관리자 지정) — 완료
- 관리 화면의 가입 신청 수를 실시간으로 갱신(Supabase Realtime). 지금은 화면을 열 때 센다
- 매치 생성·고치기·지우기, 참석 투표(도착 / 떠나는 시간), 참석자·미투표자 명단 — 완료
- 실제 출석 확정 — 스쿼드 빌더 뒤에 한다(기본값을 "스쿼드에 들어간 사람"으로 채우기 때문)
- 스쿼드 빌더(쿼터별, 프리셋과 커스텀 포메이션, 드래그, 자동 배치, 키퍼 수동 차출, 출전 / 보장 쿼터 수, 경고)
- 쿼터 보드(포메이션 보기 / 출전표 보기)
- 이미지 익스포트, 카톡 공유(이름 포함 미리보기)
- PWA manifest, Supabase 일시정지 방지용 Cron

### 2차

- 관리자 통계: 멤버별 참석률(최근 4주 / 시즌 / 전체), 투표 응답률, 노쇼율, 출전 쿼터 수(키퍼 쿼터는 따로), 포지션별 출전 vs 선호 포지션, 매치별 참석 인원 추이. 용병은 멤버 통계에서 빠진다.
- 스쿼드 빌더에 시즌 평균 출전 쿼터 수 표시

### 이후 계획

- **선수별 특이사항**: 원래 멤버 요청 목록에 있던 항목이라 우선순위가 높다. 관리자 메모와 매치별 메모로 나눌지는 그때 정한다.
- **경기 결과 기록**: 스코어, 득점, 어시스트
- 당일 변동(지각, 부상, 노쇼)이 생기면 "N쿼터부터 다시 배치". 이미 끝난 쿼터는 그대로 두고 남은 쿼터만 다시 짠다.
- 등번호(선택 입력, 선수 칩에 표시)
- 웹 푸시 알림(승인 대기, 투표 마감 알림). 안드로이드 크롬은 바로 되고, 아이폰은 홈 화면에 추가한 경우에만 된다.
