# Silver Park Rangers 스쿼드 관리 — 기획

> 최종 수정: 2026-10-23 · 상태: 풋볼매니저 24 테마와 팀 엠블럼 적용

## 1. 목적

매주 한 번 다른 팀과 경기하는 우리 팀의 스쿼드 편성을 쉽게 만든다. 참석 투표 → 쿼터별 스쿼드 편성 → 공유까지 한곳에서 끝낸다.

운영 원칙

- **비용 0원**: 비상업용이라 모든 서비스를 무료 플랜 안에서만 쓴다. 카드 등록이 필요한 플랜도 쓰지 않는다.
- **우리 팀 전용**: 관리자가 승인한 사람(멤버, 용병)만 쓸 수 있다. 한 번 뛰고 마는 용병은 계정 없이 관리자가 매치에 넣는다(그날 용병, 4장).

용어

- **매치**: 하루 일정 하나 (예: 10/25 10:00~13:00 vs OO FC)
- **쿼터**: 매치 안의 경기 하나(25~30분). 기본 6쿼터

| 프레임워크 | Next.js (App Router) + TypeScript | b-match-admin과 같은 조합 |

| 이미지 익스포트 | `next/og` | 서버에서 PNG 를 그린다. 앱 안에서 전체 화면으로 열고, "이미지 저장"(내려받기)이나 길게 눌러 저장한다 |
| 카톡 공유 | 공유 시트 · 링크 복사 + `next/og` 미리보기 이미지 | 카카오 SDK·키 없음. 8장 참고 |
| 테스트 | Vitest | 자동 배치 로직 검증 |
| 호스팅 | Vercel Hobby | 비상업용 조건에 맞음 |

무료 플랜에서 주의할 점

- Supabase 무료 프로젝트는 7일 동안 안 쓰면 일시정지된다 → Vercel Cron(하루 1회)으로 DB에 요청을 보내서 막는다.
- Supabase 무료 플랜은 활성 프로젝트가 2개까지다 → 시작 전에 남은 자리를 확인한다.
- **Supabase 프로젝트 지역은 서울(Northeast Asia)** 이다. 팀원이 모두 한국에 있어서 가까운 지역이 빠르다. 지역은 만든 뒤 바꿀 수 없어서, 처음 시드니에 만든 프로젝트를 데이터 없이 서울에 다시 만들었다(2026-10-27, 쓸 데이터가 없었다).
- 로그인은 이메일·비밀번호만 쓴다. 소셜 로그인은 다른 화면을 오가야 해서 카톡 인앱 브라우저에서 잘 깨지고(구글은 아예 막힌다, `disallowed_useragent`), 우리 팀만 쓰는 서비스라 필요하지 않다.
- **이메일 확인은 끈다.** Supabase 기본 메일 발송은 프로젝트 조직 구성원 주소로만 가고 시간당 몇 통뿐이라, 확인 메일이 팀원에게 가지 않는다. 본인 확인은 관리자 승인이 한다. 그래서 메일을 보내는 기능(비밀번호 찾기 메일 등)은 쓰지 않는다.
- 카톡은 링크 미리보기 이미지를 캐시한다 → 미리보기 URL에 `?v=수정시각`을 붙인다.
- `next/og`는 한글 폰트를 직접 넣어줘야 한다 → 필요한 글자만 남긴 Pretendard를 쓴다.
- 카톡 인앱 브라우저에서는 이미지 다운로드가 안 될 수 있다 → 초반에 실제 폰으로 확인하고, 안 되면 공유 시트(Web Share API)나 "길게 눌러 저장"으로 대신한다.
- **새 창(`target="_blank"`)을 열지 않는다.** 홈 화면에 추가한 앱(PWA)에서 새 창은 앱을 하나 더 띄워 시작 화면(로고)이 다시 뜨고, 뒤로 가기를 누르면 그 창이 닫히며 앱이 꺼진다(2026-10-21 실제 폰에서 확인). 이미지는 같은 화면 위에 덮어 열고, 주소에 `?image=` 를 남겨 뒤로 가기가 그 보기만 닫게 한다.

## 3. 사용자와 권한

권한(역할)과 구분(멤버 / 용병)은 따로 관리한다. 권한은 세 단계다.

| 권한 | 누구 | 할 수 있는 것 |
|---|---|---|
| 어드민 | 선수가 아닌 운영용 전용 계정. 팀원과 같은 로그인 화면을 쓴다 | 관리자가 하는 일 전부 + **관리자 지정·해제**, 관리자 휴면 처리, 관리자의 임시 비밀번호 |
| 관리자 | 멤버 중 어드민이 지정한 사람 | 일반 기능 + 가입 승인·거절, 멤버/용병 구분, 일반 멤버 휴면 처리, 일반 멤버의 임시 비밀번호, 매치 생성, 그날 용병, 스쿼드 편성, 통계 |
| 일반 | 승인된 멤버·용병 | 참석 투표, 공개된 스쿼드 보기, 내 프로필·비밀번호 수정 |

- 어드민 계정은 선수가 아니라서 멤버 목록·참석·스쿼드에 나오지 않는다. 그래서 `members` 가 아니라 `owners` 테이블에 둔다. 관리 화면(`/admin`)만 쓴다.
- 어드민 계정은 Supabase 대시보드에서 만들고 SQL Editor 로 `owners` 에 넣는다(docs/SETUP.md §4). 앱에서는 누구도 어드민이 될 수 없다.
- 관리자끼리 서로 휴면 처리하지 못한다. 관리자의 휴면·해제는 어드민만 한다.

| 구분 | 의미 | 누가 보나 |
|---|---|---|
| 멤버 | 정식 멤버. 관리자가 승인할 때 지정 | **관리자만** |
| 용병 | 자주 와서 직접 가입한 용병. 멤버 통계(참석률 등)에서 빠진다. 나중에 멤버로 바꿀 수 있다 | **관리자만** |
| 그날 용병 | 한 번 뛰고 마는 용병. 계정 없이 관리자가 매치에 넣는다(4장) | **관리자만** |

- 일반 사용자 화면(참석자 목록, 쿼터 보드, 공유 이미지)에는 멤버 / 용병 / 그날 용병 표시가 나오지 않는다. 이름만 나온다.
- 구분 값은 일반 사용자가 읽을 수 없게 관리자 전용 테이블에 따로 저장한다(9장 `member_admin_info`, `match_guests`).
- 계정 상태: `가입 신청 → 승인 대기 → 승인 | 거절`. 승인된 뒤에도 관리자가 휴면 처리할 수 있다. 잘못 거절했으면 거절 목록에서 다시 승인한다.
- 첫 관리자는 어드민 계정이 관리 화면에서 지정한다.

## 4. 가입 · 승인 흐름

1. 단톡방이나 자주 오는 용병에게 서비스 링크를 보낸다.
2. 로그인 화면의 "가입 신청"에서 이메일, 비밀번호, 실명, 주발, 선호 포지션, 등번호(선택)를 한 번에 입력한다 (5장).
3. 신청하면 바로 로그인된 채로 승인 대기 화면으로 넘어간다. 승인 전에는 아무 기능도 쓸 수 없다.
4. 관리 화면에 가입 신청 수가 뜬다. 관리자(또는 어드민)는 실명과 이메일을 보고 본인이 맞는지 확인한 뒤, 승인(멤버 / 용병 선택)하거나 거절한다.
5. 승인되면 바로 서비스를 쓸 수 있다.

- 가입 신청과 멤버 행은 한 번에 만들어진다(DB 가 계정을 만들 때 같이 만든다). 계정만 생기고 신청이 빠지는 일이 없다. 그래도 신청 정보가 없는 계정(대시보드에서 따로 만든 계정 등)으로 로그인하면 `/onboarding` 에서 마저 입력한다.
- **비밀번호를 잊으면** 관리자가 멤버 관리에서 임시 비밀번호를 만들어 카톡으로 알려 준다. 본인은 그걸로 로그인해서 `/me` 에서 바꾼다. 관리자의 임시 비밀번호는 어드민만 만든다(관리자끼리 서로의 계정에 들어가지 못하게). 메일은 보내지 않는다(2장).

### 그날 용병

한 번 뛰고 마는 용병은 가입시키지 않는다. 관리자가 매치 화면에서 넣는다.

- 이름, 주발, 선호 포지션, 등번호(선택)를 입력하면 그 매치에 **참석**으로 바로 들어가 스쿼드 빌더 벤치에 오른다. 도착·떠나는 시간은 빌더에서 다른 사람처럼 고친다.
- 계정이 없어서 로그인하지 않는다. 스쿼드는 공유 링크(8장)로 본다.
- 그 매치에만 속한다. 다른 매치·멤버 관리·미투표자 목록에 나오지 않는다. 매치를 지우면 같이 지워진다.
- 관리자가 이름·주발·포지션·등번호를 고치고, 뺄 수 있다. 빼면 스쿼드의 그 자리는 빈칸이 되고 골 기록은 "모름"이 된다.
- 통계에서는 다른 용병처럼 멤버 통계에서 빠지고, 매치별 출석 인원(용병 포함)에만 센다.
- 등번호는 멤버 번호와 겹쳐도 된다(남는 유니폼을 입을 수 있다). 같은 매치에 같은 번호가 둘이면 빌더가 경고한다.

### 접근 차단은 두 겹으로 한다

URL은 공개라서 누구나 접속 자체는 할 수 있다. 그래서 다음 두 겹으로 막는다.

- **화면**: Next.js `proxy.ts`(예전 이름 middleware)가 로그인 여부와 계정 상태를 확인하고, 해당 사용자를 `/login`(로그인 전에는 `/signup` 도 열린다), `/onboarding`, `/pending`으로 보낸다.
- **데이터**: Supabase 접근 정책(RLS)으로 승인된 사람만 읽고 관리자만 쓰게 한다. 브라우저에 노출되는 Supabase 키로 API를 직접 호출해도, 승인 안 된 사람은 아무것도 읽지 못한다. 화면 차단만으로 부족한 이유가 이것이다.
- 사용자가 자기 역할이나 상태를 직접 바꾸지 못하게, 해당 컬럼은 권한 설정이나 트리거로 막는다.
- 예외는 카톡 공유용 경로 하나뿐이다(8장).

## 5. 프로필 항목

이메일·비밀번호·실명만 텍스트로 입력하고, 나머지는 모두 선택형이다. 가입 신청에서 다 받고, 이메일·실명 말고는 `/me` 에서 고친다.

| 항목 | 입력 방식 | 규칙 |
|---|---|---|
| 이메일 | 텍스트 | 필수. 로그인 아이디로만 쓴다(메일은 보내지 않는다) |
| 비밀번호 | 텍스트 두 번 | 필수, 8자 이상 |
| 실명 | 텍스트 | 필수, 20자까지 |
| 주발 | 왼발 / 오른발 | 복수 선택(둘 다 고르면 양발), 최소 1개 |
| 선호 포지션 | 아래 7개 중 선택 | **3개**, 고른 순서가 우선순위. **1순위로 골키퍼를 고르면 골키퍼 하나만** 고른다(나머지는 막힌다). 골키퍼를 2·3순위로 고를 수는 있다 |
| 등번호 | 0~99 중 선택 | 선택. 같은 번호는 한 사람만(그날 용병은 빼고). 다른 사람이 쓰는 번호는 고를 수 없다 |

그날 용병(4장)은 이메일·비밀번호 없이 나머지 항목만 같은 규칙으로 관리자가 입력한다.

### 포지션 분류

| 코드 | 이름 | 비고 |
|---|---|---|
| `FW` | 공격수 | |
| `AM` | 공격형 미드필더 | |
| `WG` | 윙 | 4-4-2의 좌우 미드필더 포함 |
| `MF` | 미드필더 | 수비형 미드필더 포함 |
| `WB` | 윙백 | 풀백 포함 |
| `CB` | 센터백 | |
| `GK` | 골키퍼 | |

포메이션의 슬롯마다 이 7개 중 하나가 붙는다. 그래서 스쿼드 빌더에서 그 슬롯을 선호하는 선수를 강조할 수 있고, 자동 배치(6장)와 포지션별 출전 통계에도 쓸 수 있다.

- **4-3-3**: GK, WB×2, CB×2, MF×3, WG×2, FW
- **4-4-2**: GK, WB×2, CB×2, MF×2, WG×2, FW×2
- **커스텀**: 포지션별 인원수(센터백 3, 윙백 2 …)를 고르면 줄마다 자리를 고르게 잡아 저장한다. 키퍼는 항상 1명이다.

### 능력치 (관리자 전용, 2026-10-27)

관리자가 선수마다 능력치를 매긴다. 풋볼매니저처럼 세부 항목을 많이 두지 않고, 팀원에게 익숙한 FC 온라인(피파) 카드의 6가지에 골키퍼를 더한다.

| 능력치 | 무엇을 보나 |
|---|---|
| 속도 | 순간 속도, 전력 질주, 뒷공간 침투와 복귀 |
| 슛 | 결정력, 슈팅의 정확도와 세기, 중거리 |
| 패스 | 짧은 패스·긴 패스의 정확도, 시야, 크로스 |
| 개인기 | 볼 컨트롤, 첫 터치, 1:1 돌파, 탈압박 |
| 수비 | 마크, 위치 선정, 태클, 가로채기 |
| 피지컬 | 몸싸움, 공중볼, 체력(6쿼터를 버티는지) |
| 골키퍼(선택) | 선방, 캐칭, 킥, 나오는 판단. 키퍼를 볼 수 있는 사람만 매긴다 |

- 점수는 **1~10 정수**, 우리 팀 안에서의 상대 평가다: 9~10 팀 최고 수준(선출급) · 7~8 잘하는 편 · 4~6 팀 평균 · 1~3 약함. 화면은 같은 네 단계 색(초록 · 연두 · 노랑 · 빨강)이다.
- 매기지 않은 칸은 비워 둔다(0 이 아니다).
- 능력치 이름 오른쪽의 **? 단추**를 누르거나(휴대폰) 마우스를 올리면(데스크톱) 위 "무엇을 보나"가 뜬다 — 관리자마다 기준이 갈리지 않게.
- 🔴 **관리자(관리자 · 어드민)만 매기고 본다.** 일반 멤버는 자기 능력치도 못 본다. 멤버/용병 구분처럼 관리자 전용 표(`member_ratings`)에 둔다. 공유 링크 · 이미지에도 나오지 않는다.
- 그날 용병은 매기지 않는다(한 번 뛰고 마는 사람).

## 6. 쿼터 운영과 자동 배치

### 매치 기본값

- 6쿼터, 10:00~13:00. 관리자가 매치마다 바꿀 수 있다.
- 쿼터 시작 시각은 전체 시간을 쿼터 수로 똑같이 나눠서 정한다. 기본값이면 30분 간격으로 10:00, 10:30, … 12:30에 시작하고, 실제 경기는 그 안에서 25~30분 한다.
- 쿼터당 11명(필드 10 + 골키퍼 1). 커스텀 포메이션은 인원이 달라도 된다.

### 참석 투표

- 참석 / 불참 / 미정 중에서 고른다. 마감 전에는 몇 번이고 바꿀 수 있다.
- 투표 마감은 관리자가 매치를 만들 때 정한다. **따로 정하지 않으면 매치 시작 시각에 마감한다.**
- 참석이면 **도착 시간**과 **떠나는 시간**을 고른다. 쿼터 시작 시각 단위로 선택하고, 기본값은 "처음부터"와 "끝까지"다.
  - 예: 11:00에 도착하면 11:00 쿼터부터, 12:00에 떠나면 11:30 쿼터까지 뛸 수 있다.
- 늦게 오는 사람과 일찍 가는 사람은 같은 규칙으로 처리한다(6장 자동 배치).
- 미리 알린 늦은 도착만 받는다. 예고 없는 지각은 따로 처리하지 않는다.
- 시간은 쿼터 번호가 아니라 시각으로 저장한다. 그래야 관리자가 매치 시간을 바꿔도 "12시에 간다"는 의미가 그대로 남는다.

### 골키퍼

- **전담 키퍼**: 선호 포지션 1순위가 GK인 사람이다. 뛸 수 있는 모든 쿼터에서 키퍼를 맡고, 필드 배분에서는 빠진다. 1순위 GK가 2명 이상 오면 키퍼 쿼터를 똑같이 나눈다.
- **수동 차출**: 전담 키퍼가 불참하거나 일부 쿼터에만 있으면, 그 쿼터의 키퍼 자리는 비워두고 경고를 띄운다. 관리자가 직접 멤버를 골라 넣는다. 자동으로 뽑지 않는다.
- **키퍼로 뛴 쿼터는 출전으로 세지 않는다.** 차출된 사람도 필드 출전은 다른 사람과 똑같이 보장받는다.
- 키퍼 자리를 먼저 채우고 자동 배치를 누르면, 키퍼 자리는 그대로 두고 필드만 짠다. 차출된 사람은 키퍼로 뛰는 쿼터에서는 필드 후보에서 빠진다.

### 자동 배치 규칙

관리자가 빌더에서 "자동 배치"를 누르면 아래 순서로 전 쿼터의 필드를 채운다. 그다음 드래그로 고친다.

1. **보장 출전 수**: 필드 슬롯 총합(키퍼 자리 제외, 6쿼터 × 10 = 60)을 필드 선수에게 최대한 똑같이 나눈다.
   - 모두 n 또는 n+1쿼터를 뛴다. 사람 사이의 차이는 최대 1쿼터다.
   - 예외: 그렇게는 필드를 다 채울 수 없을 때만 상한을 n+2, n+3 … 으로 올린다. 사람이 남는데 필드를 비워 두지는 않는다. 무작위 입력 3,000개로 시험했을 때는 이 예외가 한 번도 필요하지 않았다.
   - 뛸 수 있는 쿼터 수보다 많이 줄 수는 없다. 늦게 오거나 일찍 가서 못 채운 몫은 나머지에게 다시 나눈다.
   - 예: 필드 17명이면 60 ÷ 17 ≈ 3.5 → 전원 최소 3쿼터, 그중 9명은 4쿼터.
   - 실제 참석은 **12명에서 21명까지** 오간다(2026-10-23). 전담 키퍼 1명 기준으로 12명이면 필드 11명이 60 ÷ 11 ≈ 5.5 → 전원 5쿼터, 그중 5명은 6쿼터(쿼터마다 1명만 쉰다). 21명이면 필드 20명이 전원 똑같이 3쿼터다. 이 양 끝도 테스트로 고정해 둔다.
2. **쿼터별 선발**: 앞 쿼터부터 채운다. 한 쿼터의 10명은 아래 순서로 뽑는다.
   1. **반드시 넣을 사람**: 남은 가능 쿼터를 전부 뛰어야 보장 수를 채울 수 있는 사람. 그래서 일찍 가는 사람은 앞 쿼터에, 늦게 오는 사람은 도착 직후 쿼터에 먼저 들어간다.
   2. **급한 사람**: "남은 보장 수 ÷ 남은 가능 쿼터"가 큰 사람부터. 그래서 쉬는 쿼터가 한쪽으로 몰리지 않는다.
   3. **남는 자리(n+1번째 쿼터)**: 그 쿼터 포메이션에서 아직 비어 있는 포지션을 선호하는 사람 먼저, 같으면 무작위다. 무작위라서 다시 누르면 다른 조합이 나올 수 있다.
3. **포지션 배치**: 쿼터마다 선발된 10명을 슬롯에 놓는다. 선호 1순위 3점, 2순위 2점, 3순위 1점으로 계산해서 합이 가장 큰 배치를 고른다.
4. **경고**: 다음 경우를 빌더에 표시한다.
   - 보장 출전 수에 못 미치는 사람
   - 필드 10명을 못 채우는 쿼터
   - 키퍼가 빈 쿼터
5. **다시 배치**: 자동 배치는 몇 번이고 다시 누를 수 있다. 다시 누르면 키퍼 자리는 유지하고 필드 배치는 새로 짠다(확인창을 띄운다).

자동 배치는 브라우저에서 도는 순수 TypeScript 함수로 만든다(서버 비용 없음). 위 규칙은 Vitest 단위 테스트로 검증한다.

### 자동 배치 스타일 (능력치 반영, 2026-10-27)

자동 배치 단추 옆에서 **스타일**을 고른다. 🔴 보장 출전 수 · 상한 · 도착/떠나는 시간 · 전담 키퍼 · 키퍼 쿼터 미집계는 스타일과 상관없이 그대로다. 스타일은 **누가 어느 쿼터에 뛰는지만** 바꾼다.

| 스타일 | 목표 |
|---|---|
| 기본 | 지금 규칙(위 1~5). 능력치를 보지 않는다 |
| 균등 | 쿼터마다 전력이 비슷하게 |
| 초반 집중 | 앞 쿼터일수록 전력이 높게 |
| 후반 집중 | 뒤 쿼터일수록 전력이 높게 |
| 쿼터 지정 | 관리자가 고른 쿼터(예: 강팀 상대 3 · 4쿼터)의 전력이 높게 |

- **선수 전력** = 필드 능력치 6개(속도 · 슛 · 패스 · 개인기 · 수비 · 피지컬)의 평균. 미평가 항목은 빼고 평균하고, 하나도 매기지 않은 사람(그날 용병 포함)은 이번 배치 대상의 평균으로 본다. 아무도 매기지 않았으면 어느 스타일이든 기본과 같다.
- **쿼터 전력** = 그 쿼터 필드 선수 전력의 합(키퍼는 빼고).
- 방법: 기본 규칙으로 뽑은 뒤, 두 쿼터 사이에서 두 사람을 맞바꾼다(각자 뛰는 쿼터 수는 그대로, 뛸 수 있는 쿼터로만). 스타일 목표가 좋아지는 동안 되풀이한다. 포지션 선호 점수도 같이 봐서, 자리 맞춤이 크게 나빠지는 맞바꿈은 하지 않는다.
- 균등은 기본처럼 **3쿼터 연속으로 쉬는 사람을 만들지 않는다.** 집중형(초반 · 후반 · 쿼터 지정)은 일부러 몰기 때문에 이어서 오래 쉬는 사람이 생길 수 있다 — 집중형을 고르면 **경고 창**으로 한 번 더 묻는다.
- "N쿼터부터 다시 배치"도 고른 스타일로 짠다(끝난 쿼터는 그대로).
- 능력치 · 스타일은 관리자 화면에서만 쓴다. 팀원 화면 · 공유 링크 · 이미지에는 나오지 않는다.

### 풋살 (5:5 · 6:6, 2026-10-27)

매치를 만들 때 종류를 고른다: **축구**(기본) · **풋살 5:5** · **풋살 6:6**.

- 풋살 매치에는 쿼터 · 포메이션 · 스쿼드 빌더가 없다. 대신 **팀 나누기**다: 참석한 사람을 관리자가 고른 **2팀 또는 3팀**으로 나누고, **하루 동안 고정**한다.
- 팀 인원은 똑같이(차이는 1명까지) 나눈다. 경기 인원(5명 · 6명)을 넘는 사람은 그 팀의 **교체**다. 한 팀이 경기 인원보다 적으면 경고한다(예: 5:5 로 3팀인데 13명).
- 나누는 기준은 **팀 평균 전력이 비슷하게**다(필드 능력치 평균, 위 "선수 전력"과 같다). 🔴 골키퍼 능력치는 보지 않는다 — 풋살은 키퍼도 돌아가며 본다. 포지션도 보지 않는다. 다시 누르면 전력은 비슷하면서 다른 조합이 나온다.
- 관리자가 손으로 옮길 수 있다(사람을 누르고 → 옮길 팀을 누른다). 팀 평균 전력은 관리자 화면에만 보인다.
- 저장 · 공개는 축구 스쿼드와 같다. 공개하면 팀원은 매치 화면에서 팀 명단(이름 · 등번호)을 보고, 카톡 공유 링크도 팀 명단을 보여 준다. 능력치 · 전력은 나오지 않는다.
- 참석 투표는 참석 · 미정 · 불참만 묻는다(쿼터가 없어서 도착 · 떠나는 시간은 묻지 않는다). 출석 확정은 축구와 같다.
- 경기 결과 기록과 공유 이미지는 풋살에서 아직 하지 않는다(나중에).

## 7. 화면 목록

### 화면 크기

모바일·태블릿·데스크톱에서 모두 쓴다(2026-10-21, 팀원 요청). 모바일을 먼저 짜고 넓은 화면에서 넓힌다.

| 이름 | 폭 | 배치 |
|---|---|---|
| 모바일 | 768px 미만 | 한 줄로 위에서 아래로. 카톡 인앱 브라우저가 주 무대다 |
| 태블릿 | 768px(`md`) 이상 | 카드 한 줄에 두 개, 쿼터 보드는 모든 쿼터를 한눈에, 스쿼드 빌더는 왼쪽 경기장·오른쪽 벤치 두 칸 |
| 데스크톱 | 1024px(`lg`) 이상 | 카드 한 줄에 세 개, 매치 화면은 왼쪽 투표·참석, 오른쪽 스쿼드 두 칸 |

- 본문 최대 폭은 세 가지다: 폼 하나(로그인·가입 신청·내 정보·매치 만들기) 30rem, 팀원 화면 64rem, 관리 화면 80rem.
- 쿼터 보드는 태블릿 이상에서 탭 대신 모든 쿼터와 출전표를 한꺼번에 보여 준다. 한 줄에 몇 쿼터를 놓을지는 놓인 자리의 폭으로 정한다(매치 화면 오른쪽 칸은 한 줄에 두 쿼터, 공유 링크는 세 쿼터).
- 스쿼드 빌더는 태블릿 이상에서 첫 줄 왼쪽에 포메이션, 오른쪽에 자동 배치·저장·공개를 두고, 둘째 줄 왼쪽에 경기장만(스크롤해도 붙어 있다), 오른쪽에 고른 선수·선수 표·확인할 것·특이사항을 둔다. 모바일은 포메이션 → 경기장 → 선수 표 순이고 저장 줄이 화면 아래에 붙는다.
- **색**: 다크 모드 하나다(2026-10-21, 팀 요청). 바탕은 어두운 남색 회색, 강조색(주요 단추·고른 탭·링크)은 우리 유니폼 하늘색이다. 공유 이미지·카톡 미리보기 카드도 어둡다. 화면 생김새는 아래 "테마"를 따른다.
- **경기장은 화면 높이를 넘지 않는다.** 경기장은 세로로 길어서 폭만 따라 커지면 넓은 화면에서 골키퍼가 화면 밖으로 나간다(2026-10-21, 와이드 모니터에서 확인). 높이가 화면 높이에서 머리글·여백(8rem)을 뺀 만큼을 넘지 않게 폭을 줄이고 가운데에 둔다. 낮은 화면에서도 20rem 아래로는 줄이지 않는다.

### 테마 — 풋볼매니저 24

서비스 전체를 **풋볼매니저 24** 화면처럼 꾸민다(2026-10-23, 설계안 승인). 스쿼드 빌더만이 아니라 로그인·가입부터 관리 화면, 공유 링크, 로딩 화면까지 같다.

- **머리띠**: 화면 맨 위는 우리 유니폼 하늘색 띠다(풋볼매니저의 구단 색 타이틀 바). 엠블럼, 화면 제목, 그 위에 작은 보조 줄(날짜·상대 등)을 두고, 뒤로 가기와 주요 단추도 띠 위에 놓는다. 띠 위 글자·단추는 남색이다.
- **패널**: 내용은 "어두운 머리 줄 + 본문" 상자에 담는다. 머리 줄에는 작은 굵은 제목과 오른쪽에 짧은 요약(인원수·마감 등)을 둔다. 바탕을 한 단계 더 어둡게 해서 패널이 떠 보이게 한다.
- **표**: 줄무늬, 고른 줄은 하늘색으로 감싸고, 숫자는 오른쪽 정렬·같은 폭이다. 머리글을 눌러 정렬하는 표는 정렬 중인 머리글에 하늘색 밑줄과 ▼ 를 둔다.
- **값에 붙는 색**: 자리 적합도 색(1순위 초록 · 2순위 연두 · 3순위 노랑 · 선호 아님 빨강)을 참석률·응답률에도 같은 네 단계로 쓴다(90% · 75% · 60% 기준). 경기 결과는 승 초록 · 무 회색 · 패 빨강 칸이다. 색만으로 구분하지 않고 숫자·글자를 같이 둔다.
- **탭**: 쿼터 탭·기간 탭 같은 하위 탭은 글자 아래 하늘색 밑줄로 고른 것을 표시한다.
- **관리 화면 메뉴**: 데스크톱은 풋볼매니저처럼 왼쪽 메뉴(아이콘 + 이름)이고, 태블릿 이하는 지금처럼 위쪽 메뉴다. 같은 메뉴를 화면 크기에 따라 옮길 뿐 두 번 그리지 않는다.
- **모서리**: 각지게. 패널·단추·입력칸 6px, 칩·작은 칸 4px.
- **경기장**: 잔디 줄무늬를 넣는다.
- **엠블럼**: 팀 엠블럼(둥근 크레스트, 2026-10-23 받음)을 머리띠 · 관리 메뉴 · 로그인 · 매치 미리보기, 파비콘 · 홈 화면 앱 아이콘, 카톡 미리보기 기본 이미지, 스쿼드 이미지 머리글에 쓴다. 원본 하나에서 모든 크기를 만든다(docs/SETUP.md §8).
- 누르는 것 44px 이상, 입력칸 글자 16px 이상(화면 공통 규칙)은 그대로 지킨다. 영문 대문자 머리글·별점 같은 게임 장식은 쓰지 않는다.

**매치 결과**: 하루 매치의 승·무·패는 그날 쿼터 점수를 더한 합계로 정한다(합계 4 : 2 면 승). 결과를 남긴 쿼터가 없는 매치는 결과가 없다. 통계의 "쿼터 전적"(쿼터를 한 경기로 센 것)과는 따로다.

### 일반 (멤버 · 용병)

| 경로 | 내용 |
|---|---|
| `/` | **다음 매치**(상대·킥오프·장소, 내 응답과 마감, 참석·미정·불참 인원 막대, 투표 단추), **최근 폼**(결과를 남긴 최근 매치 5개의 승·무·패와 지난 매치 점수), 그 뒤의 다가오는 매치와 내 투표 상태 |

| `/me` | 주발, 선호 포지션, 등번호 수정(실명은 관리자만 바꾼다). 바꾼 선호 포지션은 다음 자동 배치부터 쓴다. 비밀번호 바꾸기, 앱으로 설치 |

**내 정보 · 로그아웃(전 팀원 화면 공통, 2026-10-23)**: 팀원 화면(홈 · 매치 · 내 정보) 맨 아래에 "내 정보 · 로그아웃" 줄이 늘 있다. 어느 화면에서든 내 정보로 바로 간다(홈은 머리띠 오른쪽 "내 정보"도 그대로). 관리 화면 메뉴에도 로그아웃 옆에 "내 정보"가 있다(관리자만 — 어드민 계정은 선수가 아니라서 내 정보가 없다). 승인 전 화면(대기 · 온보딩)에는 내 정보가 없고 로그아웃만 있다.

**앱으로 설치(PWA, 2026-10-23)**: 브라우저의 설치 안내는 믿을 수 없다 — 안드로이드 크롬은 자동 배너를 한 번 닫으면 몇 달 동안 다시 띄우지 않고, 아이폰은 자동 안내가 아예 없고, 카톡 인앱 브라우저에서는 설치가 안 된다. 그래서 우리가 **"앱으로 설치" 패널**을 둔다.

- 로그인 · 홈에는 "다음에"로 접을 수 있게(그 기기에서 2주 동안 숨김), 내 정보에는 늘 둔다. 이미 앱으로 열었으면 보이지 않는다.
- 기기마다 다르게 안내한다.
  - 크롬 · 삼성 인터넷 · 엣지(설치 창을 띄울 수 있을 때): "앱 설치" 단추 하나로 설치 창을 띄운다.
  - 설치 창을 못 띄우는 안드로이드(한 번 거절했거나 아직 조건이 안 됨): 브라우저 메뉴(⋮) → "앱 설치"/"홈 화면에 추가".
  - 아이폰 · 아이패드: 공유 버튼 → "홈 화면에 추가" → "추가". 설치한 앱에서 한 번 더 로그인해야 한다(아이폰은 앱과 사파리의 로그인이 따로다).
  - 카톡 인앱 브라우저: "다른 브라우저로 열기" 단추(카톡의 바깥 브라우저 열기 주소)와, 안 될 때를 위한 손 안내(안드로이드 ⋮ → 다른 브라우저로 열기, 아이폰 공유 → Safari로 열기).
  - 그 밖의 앱 안 브라우저(네이버 · 밴드 · 인스타그램 등): 다른 브라우저로 열라고 안내한다.
- 크롬이 설치 창을 띄우려면 서비스 워커가 있어야 한다. 그래서 **최소한의 서비스 워커**를 둔다: 인터넷이 끊겼을 때 화면 이동만 "연결 안 됨" 안내 화면으로 바꾸고, 데이터·화면은 캐시하지 않는다(늘 서버에서 새로 읽는다).

**로딩 표시(전 화면 공통)**: 카톡 인앱 브라우저는 앱 안 화면 이동에 자체 로딩 표시가 없어서, 없으면 멈춘 것처럼 보인다.

- 화면 이동·서버 요청 중에는 맨 위에 얇은 로딩 바가 뜬다(0.15초 넘게 걸릴 때만 — 금방 끝나면 깜빡이지 않는다).
- 화면을 누르면 그 자리에 바로 "불러오는 중이에요"가 뜨고, 내용이 오면 바뀐다(`loading.tsx`). 관리 화면은 메뉴를 그대로 두고 본문만 바뀐다.
- 저장·투표 같은 제출 단추는 보내는 동안 막히고 스피너가 돈다. 단추가 여럿이면 누른 단추에만 돈다.

**화면 공통 규칙(UI 다듬기, 2026-10-22)**: 한국 웹사이트에서 흔히 쓰는 방식에 맞춘다.

- 드롭다운은 꺾쇠를 오른쪽 안쪽(16px)에 그리고, 입력칸은 바탕보다 살짝 밝게 채운 칸에 잘 보이는 테두리(대비 3:1 이상), 누르면 강조색 테두리다. 글자는 16px 이상(아이폰 자동 확대 방지).
- 한글은 어절 단위로 줄바꿈한다. 누르는 것은 44px 이상이고 누르는 동안 살짝 흐려진다.
- 확인은 앱 확인 창(휴대폰은 아래에서 올라온다), 저장 결과는 화면 아래 토스트, 뒤로 가기는 ‹ 꺾쇠 + 돌아갈 화면 이름이다.
- 막힌 제출 단추 아래에는 남은 항목을 보여 준다("남은 것: 실명 · 선호 포지션 2개 더").
- 매치 만들기는 가장 늦은 매치의 다음 주 같은 요일·시간·쿼터 수·장소로 미리 채운다.
- 글꼴은 Pretendard(무료 OFL)를 우리 서버에서 글자 범위별 조각으로 내보낸다.

**출전표**는 선수 × 쿼터 표에 출전 쿼터를 ●로 표시한 것이다. 6쿼터면 포메이션 그림 6장보다 "나 언제 뛰지?"를 찾기 쉽다.

**유니폼**: 경기장 위 선수는 **유니폼 모양 안에 등번호**다(번호가 없으면 포지션 코드). 필드는 우리 유니폼 색(맨시티 하늘색보다 조금 밝은 하늘색), 키퍼는 노랑, 빈자리는 점선 유니폼이다(2026-10-21). 쿼터 보드·스쿼드 빌더·포메이션 미리보기·공유 이미지가 같다.

### 스쿼드 빌더

생김새는 **풋볼매니저 24 전술 화면**이다(2026-10-21, 팀 요청). 모바일·태블릿은 풋볼매니저 모바일처럼 같은 내용을 위아래로 쌓는다.

- 쿼터 탭(전술 슬롯처럼 쿼터마다 시간·포메이션), 경기장, 선수 표를 같이 띄운다.
- 경기장 유니폼 안에는 등번호를, 자리 포지션은 유니폼 왼쪽 위에 작게 둔다(번호가 없으면 유니폼에 포지션).
- **선수 표**(풋볼매니저 선수 선택 목록): 이 쿼터 **선발**(키퍼부터 수비 · 미드필드 · 공격 순, 같은 줄은 왼쪽부터), **벤치**(그 쿼터에 뛸 수 있지만 아직 배치 안 된 사람), **못 옴**(그 쿼터에 없는 사람과 시간). 넓은 자리에서는 한 줄짜리 표, 좁은 자리에서는 두 줄짜리 행이다.
- **자리 적합도**(풋볼매니저의 포지션 익숙도): 그 자리가 선호 1순위면 초록, 2순위 연두, 3순위 노랑, 선호가 아니면 빨강 점. 자동 배치의 선호 점수(6장)와 같은 기준이다.
  - 경기장 이름표와 선발 줄 앞에 앉은 사람의 적합도 점이 붙는다.
  - 자리를 고르면 벤치를 그 자리에 맞는 사람부터 놓고 몇 순위인지 글자로 보인다.
  - 선수를 고르면 경기장 자리마다 그 선수에게 맞는 정도를 유니폼 테두리 색으로 보인다(맞지 않는 자리는 표시하지 않는다).
- 선수를 고르면 선수 표 위에 그 선수 칸이 열린다: 선호 포지션·주발·시간, 빼기, 당일 시간 바꾸기, 특이사항.
- "자동 배치" 버튼으로 전 쿼터의 필드를 한 번에 채운다(6장).
- 키퍼 자리가 비면 경고가 뜬다. 관리자가 아무 멤버나 키퍼 자리로 드래그해서 차출한다.
- 포메이션 프리셋을 고르거나 커스텀 포메이션을 불러온다. 현재 배치를 새 포메이션으로 저장할 수도 있다.
- 벤치와 슬롯 사이, 슬롯과 슬롯 사이를 드래그로 오간다.
- 선수 표의 줄에는 다음을 표시한다.
  - 출전 쿼터 수 / 보장 쿼터 수 (예: 3/3). 키퍼로 뛴 쿼터는 "키퍼 1"처럼 따로 표시하고 출전 수에는 넣지 않는다.
  - 쿼터별 출전 칸(출전표 한 줄): 칸마다 쿼터 번호를 적고 필드는 유니폼 색, 키퍼는 노랑으로 채운다. 쉼은 빈 칸, 못 옴은 흐린 번호. 지금 쿼터는 테두리
  - 뛸 수 있는 시간
  - 선호 포지션(주발은 선수를 고르면 보인다)
  - 올해 평균 출전 쿼터
  - 용병 표시(관리자 화면이라서 보임). 그날 용병도 용병으로 보인다
- 같은 매치에 같은 등번호가 둘 이상이면 경고한다(그날 용병은 멤버 번호와 겹칠 수 있어서).
- 이전 쿼터를 복사해서 시작할 수 있다.
- 관리자가 "공개"를 누르기 전에는 멤버에게 보이지 않는다.
- 이미지 익스포트: 쿼터별 한 장씩, 6쿼터를 2×3으로 모은 한 장, 출전표 한 장.
  - **저장하면 공개 전에도 관리자는 쿼터별·출전표 이미지를 본다.** 마지막으로 저장한 배치로 그리고, 관리 화면 아래 주소(`/admin/matches/[id]/squad/image`)라 관리자만 열린다(공개 전 스쿼드는 RLS 가 관리자에게만 준다). 이 이미지는 캐시하지 않는다. 팀원은 공개 뒤에 공유 링크로 본다.

## 8. 카톡 공유

- 공유 카드에 선수 이름이 들어간다.
- **공유 링크 페이지(`/s/[share_token]`)는 로그인 없이 쿼터 보드·출전표를 보여 준다.** 카톡에서 누르자마자 볼 수 있게 하려는 것이다. 링크를 아는 사람은 이름·등번호와 배치를 볼 수 있지만, 멤버/용병 구분·참석 명단·이메일은 보이지 않는다. 계정이 없는 그날 용병도 이 링크로 스쿼드를 본다. 링크는 관리자가 스쿼드를 공개한 매치에만 생긴다. 이 화면도 로그인 뒤에만 보이게 하려면 공유 페이지 한 곳만 고치면 된다.
- 카카오 서버는 로그인 없이 미리보기를 가져간다. 그래서 공유 전용 공개 경로 `/s/[share_token]`을 따로 둔다.
  - 데이터는 DB 함수 `shared_squad` 하나로만 준다. 스쿼드를 공개한 매치만, 이름과 배치만 준다.
  - `share_token`은 추측할 수 없는 랜덤 값이다. 매치 번호를 바꿔 넣는 식으로 다른 매치를 볼 수 없다.
  - 이미지 주소에는 **그려지는 내용의 버전**(매치 날짜·시간·장소·상대 + 배치·이름·등번호)이 붙는다. 내용이 바뀌면 주소가 바뀌어 카톡이 새 이미지를 가져간다. 사람을 가리키는 값은 버전에 넣지 않아서 관리자·팀원·공유 링크가 같은 그림에 같은 주소를 쓴다.
  - 같은 주소는 같은 그림이라 **기기에 오래 캐시**한다. 한 번 만든 쿼터별·출전표 이미지는 다시 눌러도 새로 만들지 않는다. 공개 이미지는 서버(CDN)에 하루만 두고(공개를 취소하면 하루 안에 사라진다), 공개 전 이미지는 그 기기에만 둔다. 이미지 그림을 바꾸면 `IMAGE_DESIGN` 을 올린다(안 올리면 예전 그림이 남는다).
  - 공유는 카카오 SDK 없이 한다. 공유 시트가 있으면 그것을, 없으면 링크를 복사해 단톡방에 붙여 넣는다.
- 미리보기 이미지에는 1쿼터 포메이션(이름 포함)과 "6쿼터 · 18명 · 10:00~13:00" 같은 요약을 넣는다. 카드 한 장에 66명분 이름을 다 넣으면 읽을 수 없어서다. 전체는 링크나 익스포트 이미지로 본다.

## 10. 단계별 범위

### 1차 — MVP (바로 다음 매치부터 쓰기)

- 가입 신청, 승인 게이트(화면 + RLS) — 완료. 처음엔 카카오 로그인 + 온보딩이었다가 이메일 가입 신청으로 바꿨다(2026-10-21, 2장)
- 어드민 전용 계정, 멤버 관리(승인 시 멤버 / 용병 지정, 휴면, 어드민의 관리자 지정) — 완료
- 관리 화면의 가입 신청 수를 실시간으로 갱신(Supabase Realtime) — 완료. 관리 화면을 열어 둔 동안 가입 신청이 들어오면 새로 그린다.
- 매치 생성·고치기·지우기, 참석 투표(도착 / 떠나는 시간), 참석자·미투표자 명단 — 완료
- 실제 출석 확정 — 완료. "스쿼드대로 확정"(스쿼드에 든 사람 출석, 나머지 불참) 뒤에 한 사람씩 고치고, 투표 없이 온 사람을 더한다.
- 스쿼드 빌더(쿼터별, 프리셋 포메이션, 자동 배치, 키퍼 수동 차출, 출전 / 보장 쿼터 수, 경고, 이전 쿼터 복사, 저장·공개) — 완료
  - 넣고 빼기는 **탭 두 번**(고르고 → 놓기)과 **드래그** 둘 다 된다. 드래그는 마우스는 8px 움직여야, 손가락은 0.2초 길게 눌러야 시작해서 탭·스크롤과 부딪히지 않는다(dnd-kit). 벤치 → 자리는 넣기, 자리 → 자리는 바꾸기, 자리 → 벤치는 빼기.
  - 커스텀 포메이션 저장 — 완료. 좌표를 찍지 않고 **포지션별 인원수를 고르면 자리가 저절로 잡힌다**(키퍼는 항상 1명, 필드 1~10명).
- 쿼터 보드(포메이션 보기 / 출전표 보기) — 완료
- 이미지 익스포트(쿼터별 시트 · 출전표 PNG), 카톡 공유(이름 포함 미리보기 카드) — 완료
- PWA manifest(홈 화면에 추가), Supabase 일시정지 방지용 Cron(매일 03:00 UTC) — 완료

### 2차

- 관리자 통계(`/admin/stats`) — 완료. 기간은 최근 4주 / 올해(=시즌) / 전체. 지난 매치만 센다.
  - **참석률**: 실제 출석을 정한 매치 중 온 비율. 출석을 정하지 않은 매치는 넣지 않는다. 가입(승인) 전 매치도 넣지 않는다.
  - **응답률**: 가입 뒤 지난 매치 중 투표한 비율.
  - **노쇼율**: 참석으로 투표하고 출석을 정한 매치 중 안 온 비율.
  - **출전**: 필드 쿼터 수와 스쿼드에 든 매치당 평균. 키퍼 쿼터는 따로 센다.
  - **포지션별 출전**과 **선호 포지션에서 뛴 비율**.
  - **매치별 실제 출석 인원 추이**(용병 포함, 차트 + 표).
  - 용병은 멤버 통계에서 빠진다. 낼 수 없는 값은 0 이 아니라 –로 보인다.
- 스쿼드 빌더 벤치에 올해 평균 출전 쿼터 표시 — 완료

### 이후 계획

- **선수별 특이사항** — 완료. **매치마다 따로** 쓰고 **관리자만** 본다(멤버 본인도 못 본다). 스쿼드 빌더에서 선수를 고르면 바로 쓰고, 경기장 옆 "특이사항"에 그 매치의 메모가 모여 보인다. 200자까지, 비우고 저장하면 지운다. 공유 링크·이미지에는 나오지 않는다.
- **경기 결과 기록** — 완료. 쿼터마다 남긴다(하루 6경기라서).
  - 우리 점수 = 그 쿼터의 골 기록 수. 골마다 득점자·도움을 남기고, 모르거나 상대 자책골이면 "모름"으로 둔다. 그래서 점수와 득점자 목록이 어긋나지 않는다.
  - 상대 점수는 쿼터마다 숫자로 남긴다. 점수도 골도 없는 쿼터는 전적에 넣지 않는다. 그래서 0:0 으로 끝난 쿼터는 "무실점"으로 남긴다. 상대 점수는 `− 숫자 +` 로 고친다.
  - 관리자 매치 화면에서 기록하고, 팀원은 매치 화면에서 합계·전적·쿼터별 득점자를 본다.
  - 통계에 쿼터 전적(승·무·패), 득실, 멤버별 골·도움이 더해진다.
- 당일 변동(지각, 부상, 노쇼) — 완료.
  - 빌더에서 선수를 고르면 그 사람의 도착·떠나는 시간을 관리자가 바로 고친다(투표 응답은 그대로).
  - "N쿼터부터 다시 배치"는 끝난 쿼터를 그대로 두고 남은 쿼터만 다시 짠다. 이미 뛴 쿼터를 더해 보장 수를 다시 계산하므로, 앞에서 덜 뛴 사람이 남은 쿼터에 먼저 들어간다.
- 등번호 — 완료. 경기장 위 선수는 유니폼 안에 번호(없으면 포지션 코드), 출전표는 이름 앞에 번호. 관리자 스쿼드 빌더는 자리 포지션을 유니폼 왼쪽 위에 작게 둔다(7장 "유니폼").
- 이메일 가입으로 바꾸기(2026-10-21) — 완료. 카카오 로그인을 빼고 이메일·비밀번호 가입 신청(4장), 선호 포지션 3개(1순위 GK 면 GK 하나), 관리자의 임시 비밀번호, `/me` 비밀번호 바꾸기.
- UI 다듬기(2026-10-22) — 완료. 드롭다운·입력칸·확인 창·토스트·뒤로 가기·남은 항목 안내, 상대 점수 `− 숫자 +`(0:0 은 무실점), 빌더 적합도 범례·확인할 것 묶기, 새 매치 미리 채우기, Pretendard(7장 "화면 공통 규칙").
